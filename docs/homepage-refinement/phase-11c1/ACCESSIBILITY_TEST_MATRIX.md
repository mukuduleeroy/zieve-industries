# Accessibility verification matrix

Phase 11C.1 · 18 November 2026 · readiness preparation only.

## Reproduction and evidence rules

Use the unchanged production build: `npm run build`, then `npm run start -- --hostname 127.0.0.1 --port 3102`. Browser suite reproduction: `PLAYWRIGHT_BROWSERS_PATH=/private/tmp/zieve-playwright npm run test:e2e` (browser path is environment-specific). Record build/source hashes, OS/browser/AT versions, viewport, zoom, input method, expected/actual behaviour and screenshots/spoken output. Restore zoom and motion preferences after each session. Do not submit a real enquiry or send mail.

### Automated scope and limitations

[Full log](evidence/playwright.log), [repeat log](evidence/repeat-playwright.log). Failing assertion is `tests/e2e/phase-11b.spec.ts:87`: expected image height/width 1.2 at the desktop breakpoint, read approximately 0.74997. Test immediately reads bounds after `setViewportSize`; an independent evidence-only probe recorded six stale immediate reads in 35 resizes and correct aspect ratio in all35 after two animation frames, supporting a settling race rather than establishing test closure. See `evidence/breakpoint-probe.json`. No tests were edited, skipped or weakened and no green full-suite claim is made.

Fresh scanner and contrast details are summarized in EXECUTIVE_READINESS and `evidence/current-axe.json` / `evidence/contrast.json`. Automated results cannot establish WCAG conformance, screen-reader usability or native zoom completion.

Guides for manual operators: [Safari zoom](https://support.apple.com/guide/safari/zoom-in-on-webpages-ibrw1068/mac), [Firefox font size and zoom](https://support.mozilla.org/en-US/kb/font-size-and-zoom-increase-size-of-web-pages), [NVDA User Guide](https://download.nvaccess.org/documentation/userGuide.html). Use current native controls and record actual tested versions.
